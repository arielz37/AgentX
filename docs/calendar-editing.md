# 日历修改、删除与连续对话（v7）

## 用法

本轮需要一起更新 AgentX App 和 Mac 服务（RPC5，新任务v7），日历需完全访问权限。Mac 仍运行 `启动 AgentX.command`，旧 PhoneAgent 不更新。默认测试模式下只能改删标题带 `AgentX Test ` 的事项；关闭测试模式后可操作授权日历的普通可写事项。

在同一助手依次说“明天下午三点到四点练琴，不用提醒”→“把刚才那个改到下午五点”→“删掉刚才那个”。模型依据近期上下文理解目标，先读真实日历，再选择唯一候选、决定改动字段。重名且无法区分时询问，不凭标题随便选。历史命令不自动重放，报告中的实际执行状态独立于模型解释。

- 修改：标题、开始/结束、时区、全天、地点、备注、链接和0–2次相对提醒。未指定字段保持原值，明确清空备注/链接用空字符串，移除提醒用空数组。
- 删除：单次发生；用户明确要求“本次及以后”时才调用对应 EventKit scope。无邀请人、可写日历才能改删，避免触发未授权外发。
- 查询：一个日历年，例如“查询明年全年的日程”，边界按当地日历计算，包含闰年；超过2000个发生项要求缩小范围，不根据残缺占用建议空闲。
- 全天自动安排：“下周找一个完整空闲日整理资料，全天，不用提醒。”支持完整1天或连续多天；有任何参与忙闲的占用就不算完整空闲日。重复自动择时仍不支持，固定时间创建重复日程保留。

## 执行与可靠性

`首轮模型理解/复核 → 手机读取候选快照 → 模型结合原话与上下文选择目标/最小补丁并复核 → 持久化不可变决策 → 手机重新取目标、核对版本、检查冲突 → EventKit save/remove → 新 EventStore 独立读回`。

`CalendarMutation.swift` 定义模型/手机共同契约；`CalendarMutator.swift` 只扩展已有 RPC 宿主的 EventKit 能力，不新建自动化框架。复用已有连接、租约、任务存储与报告。修改/删除持久化账本在手机沙盒独立保存，发起写入前先记录 reservation；同任务/事项 ID 跨进程重试不重复操作，未知执行结果不盲目再发。新文本提交仍是新任务，不属于全局文本去重。

执行前重新读取同一个事件发生项，比对标题、起止、时区、备注、提醒、重复元数据、修改时间等指纹；发现外部变化或删除则拒绝覆盖。改期检查排除原事件自身，保留其他发生项及其他事件的占用。同批后续操作能看到先前写入，部分成功逐项记录。检查和写入之间没有跨应用事务锁，不能保证消除所有竞争。

新建重复系列检查首日起一年内所有可可靠展开的发生项，也检查系列内自身重叠。有限系列全部覆盖为 `full_series`；无限或更长系列为 `one_year_horizon`，不能宣称整个系列无冲突。遇到无法确定的夏令时当地时间边界拒绝保存，避免跳过发生项后误报安全。只读节假日、标为空闲、取消事件以及用户选择的忙闲来源沿用同一策略。

## 范围和隐私

- 同一助手最近六轮输入、回答、状态及每轮至多20个事件摘要进入新请求上下文；全能助手与日程助手分开。长历史不会全部发送，跨模块指代和超出范围的指代需要补充。
- 改删候选最多2000个，模型收到标题、日期、时区、日历名称、可写/重复标记、地点、备注和链接。设备事件 ID 与指纹留在手机；模型仅用本次快照的临时引用。所有候选文本按不可信数据处理。
- RPC/原始报告只留本机忽略目录；普通查询的回答仍由实际接口数据交给模型生成，不用代码拼正文。
- 重复规则编辑、整个系列整体改时未实现；可改指定一次发生。`future_events` 调用后的读回当前只核验选中的那次，报告为 `saved_unverified` / `target_verified_series_unverified`，不能以此证明全部未来实例都正确。删除已经过去的系列部分不被“本次及以后”覆盖。
- 单次执行窗口仍最多45秒，模型步骤增加超时机会。窗口过期只保存决策，需用户主动继续才写入；新一轮恢复也重新核对目标及冲突。普通 iOS App 不被当作永久后台服务器。

## 验证

```sh
bash scripts/test.sh
# 仅合成数据调用已配置模型，不连接手机、不改真实日历
python3 scripts/check_calendar_v7.py --live
```

回归覆盖一年/闰年边界、全天连续日期和23/25小时夏令时、重复后续发生冲突、相邻不冲突、自己与自己重叠、最小字段修改、目标指纹变化、改期排除自身、删除读回、更新/删除跨实例去重、未知结果不重试，以及候选/决策的真实数据绑定。EventKit 替身验证不能替代真实手机系统行为。

本轮真机验收尚未完成。安装后应在测试模式创建唯一标题事项，连续改期→查询→删除→查询核对；再分别测试一年读取、全天择时，以及故意占用冲突。用户在游戏期间的本版完整链路仍需单独验证，不能沿用旧版结论。

开发中的模型实验发现两类错误：事项编号没有遵守协议，以及将“改到四点”误解成延长结束；另有全年查询被误当成“只能查提交日起一年内”。已细化模型工具契约、区分改期与延长，并向复核提供查询起点对应的准确上限。没有用关键词代码代替模型理解，修复前合成失败样本保存在 evidence/calendar-v7-probes-before-*.json；有限样例通过不能保证所有表达都正确。

本轮本机结果：63项 Python 测试、8组 Swift 校验、4组 EventKit 替身程序全部通过；iOS 真机目标签名构建通过；最终7个真实模型合成样例通过（跨消息目标日期、保持时长改期、删除目标、重名澄清、一年查询、全天路由、全天选时）。模型自动选时来源标记也被编码进工具 schema，避免被误写成用户明确时间。汇总见 `../evidence/calendar-v7-validation.json`，模型结果见 `../evidence/calendar-v7-model-probes.json`。本轮版本已安装、启动，Mac 服务已重启；只读 RPC 确认 app_id=agentx、协议5、完全日历访问、原生手机执行宿主。新增业务功能的真机验收仍待用户提交任务。

后续口语真机测试暴露的全天读回、上下文以及手动操作共存问题，见 [短测试修复记录](short-test-repair.md)。历史目标现在由模型在读取前绑定，再用当前 EventKit 状态形成最小修改；不通过旧记录自动恢复用户已删除的事项。
