# AgentX 架构与技术决策

## 原生能力与用户界面分离

AgentX 由 SwiftUI iPhone App、Mac Python worker、GPT 模型接口组成。手机持有日历权限和执行账本；Mac 负责模型调用、流程协调与本地报告。两端通过 JSON-RPC 和已配对设备转发器通信，默认端口 45679。完整源码在本仓库根目录，不需要子模块。

日历执行选择 EventKit：任务直接在这台 iPhone 的系统数据层完成，不打开日历界面，不抢游戏画面、键盘或焦点。原型阶段用 XCTest 验证过设备控制，但真机游戏实验出现 Automation Running 水印和停手变暗；因此当前 App 不运行 XCTest，不复用 GUI 点击来完成日程业务。RPC 传输可复用，具体执行由原生 API 承担。

查询、空档判断、修改目标定位和保存后读回需要完整日历权限，write-only 不满足这些要求。首次权限申请只在用户主动准备阶段进行。手机前台单次窗口最长 300 秒，后台最长 45 秒且受系统裁量，过期后需用户显式继续。这是有限时间任务，不是永久后台服务。

## 模块化前端

`AssistantModule` 定义名称、图标、主题、欢迎语与示例。全能助手和日程助手共用 `AssistantChatView`，任务按 `assistant_id` 分组，草稿独立。日程模块不匹配的输入可转到全能助手草稿，不会自动发送。邮件、短信等能力目录是预留入口，尚未具备执行能力。

对话卡片来自真实 `PlanJob`。状态、自然语言答复和可展开执行证据分别展示；浏览报告不重新执行任务。新提交冻结同助手最近六轮摘要供模型理解“刚才那个”等指代；历史是上下文，改删前仍读取当前日历，不能把旧对话当成最新状态。

## 模型理解，受限工具执行

当前 RPC 协议为 5，新任务版本为 8，保留历史任务读取兼容。`creation_inventory.py` 先清点活动并审查活动与属性的边界，再由 `agentx_model.py` 生成范围判断与计划并独立复核。这些阶段共享 180 秒预算；后续模型阶段最多 120 秒。模型请求流式接收但只使用完整响应，临时错误有限重试，完成阶段先持久化。详见 [模型恢复](model-reliability.md) 与 [清单/答复恢复](answer-recovery.md)。

固定路由覆盖创建、查询、自动安排、改删，以及不支持、需澄清和混合请求。模型决定语义、参数、合理缺省及所需能力，不直接生成可执行 RPC 方法或任意代码。两端检查协议和参数；重要事实未知时保留空缺，不猜测真实约定。混合请求目前整体不执行。

- **查询**：模型确定范围 → 手机 `CalendarReader` 读取 EventKit → `CalendarAvailability` 合并忙闲区间 → 模型结合原问题回答。最长一个日历年。节假日展示与占用分开，用户可调整哪些日历参与忙闲。
- **自动排程**：先查真实空档 → 模型选择候选并复核 → 校验所选时段确实位于空档 → 写前再次检查冲突。支持单次定时与全天，重复自动择时尚未支持。
- **改删**：先读实际候选 → 模型绑定目标与最小改动 → 手机重新检查版本和权限 → 执行并验证。用户手动修改或删除时，以最新接口结果为准。
- **创建**：逐项校验 → 持久化去重 → 检查冲突 → 保存 → 读回比较。每项独立记录，支持部分成功；重复创建检查一年范围内发生项，并说明覆盖边界。

## 可靠执行与真实回答

任务、提交内容、已复核计划、执行 lease 与结果持久化。发送写指令前 Mac 先记录“结果未知”；只有确认尚未写入的界面过渡延期才能安全重试。手机账本在保存前落盘，同任务/事项 ID 跨进程去重；相同 ID 内容冲突拒绝执行。无法确认结果时不自动另建，不承诺跨 App 或重新提交文本的全局去重。

`CalendarBridge` 生命周期内复用执行 store 与验证 store，独立验证 store 在读回前 reset，兼顾连接数量和新鲜度。保存与验证状态分开，未读回不能宣称 verified。冲突策略由各条目真实结果决定，模型表述不能覆盖失败。

所有问答与执行总结遵循 **真实接口记录 → 模型结合原需求生成自然语言 → 独立复核 → 持久化 → 手机展示**。代码核对答复中逐项状态的依据，不拼接模板冒充模型回答。答复失败与日历执行失败独立；“重新生成答复”复用原执行快照和独立 retry ID，只重做回答，不重放日历操作。

## 运行与数据边界

`AgentXConfig.plist` 是端口与协议的共同配置；客户端校验 app_id 与协议，拒绝错误宿主。启动器仅复用路径、端口和设备一致的本项目转发器，遇到其他进程占用不强制终止。身份字段是防混线检查，不是密码认证；原型仅面向可信 Mac 与配对设备，不应暴露在公共网络。

模型 Key 只在 Mac 的环境或项目 `.env` 中，手机不保存 Key。发送给模型的数据包括当前原文、必要近期对话摘要、本次相关日历记录与执行证据。`data/`、`artifacts/`、`.runtime/` 和签名文件只在本机。API `store:false` 不等于第三方零保留承诺。

## 复用来源与扩展原则

RPC server、Python RPC 传输与 CoreDevice/usbmuxd 转发复用并改编自 Rounak 的 PhoneAgent，保留 `LICENSE.PhoneAgent`。日历、模型协议、可靠执行与模块前端属于本项目演进。`SOURCE_SNAPSHOT.json` 记录初始快照的来源与原始哈希，不是当前文件校验清单；旧路径仅作归属说明，无运行依赖。

新模块遵循模型优先：获取接口数据，让模型理解需求、选择工具与参数，再执行并依据结果决定后续动作。代码承担真实系统能力、授权、参数合法性、精确计算、冲突和去重等执行约束。先证实原生 API 的能力与前后台边界，再增加模块和工具白名单。发送类动作需单独设计收件人与确认流程，不能猜测联系人身份。

Debug 的 `--agentx-preview` 使用独立合成数据，不启动服务或读取真实任务；预览图不是实际执行证据。
