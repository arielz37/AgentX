# 写入前的模型复核

2026-09-29：新增 Mac 端一次独立复核。不恢复已回退的日期编译器、全天写入适配，不修改手机执行协议。

## 流程

原文 + 手机冻结提交时间/时区 → GPT 首稿 → 独立 GPT 复核 → 原有参数校验 → 手机校验/保存/读回。

复核使用当前 `WELLPHONE_MODEL`（默认 gpt-4.1-mini），单独的请求和审查提示，不沿用首稿会话、不复用“重新规划”角色指令。检查事项遗漏、日期/自然周、时长、重复、提醒、备注/链接、关键空缺和来源说明。

- `pass`：issues 为空且无修正计划，沿用首稿。
- `correct`：必须给问题和完整修正计划，再通过现有契约校验；保留前后差异。
- `block`：不执行，说明原因。
- 拒绝、超时、不完整输出、矛盾结论、空计划或校验失败均不放行首稿。不增加第三次调用、不自动重试。

代码向模型提供提交时区的本周/下周范围，以及候选时刻是否晚于提交时刻、星期和时长等比较事实。这些是复核参考，不是自然语言日期编译器，不直接决定或改写事件日期。模型仍可能忽略事实或判断错误。

生成和复核共用 22 秒处理预算，第二次请求仅获得剩余时间，迟到结果不执行。网络库超时不等于严格的进程墙钟中断。后台系统窗口仍可能提前结束；worker 在模型处理后重新查询手机状态，沿用已有人工继续/未知结果不重放机制。

## 记录与部署

`wellphone-data/<任务ID>.json` 保存 `model.draft`、首稿 API 元数据、`generation_seconds`、`review_seconds`、`review.result`、复核 API 元数据、`review.changes`。复核失败同样保存诊断信息。Markdown 显示复核结论、问题和修改；手机仍显示最终字段及原有执行结果，尚无专门复核面板。

只需重启 Mac worker；日常入口仍是“一键启动”。已生成的历史不可变计划不重新解析、不追加复核、不重写日历。历史报告明确标示没有复核记录。无需更新手机、密钥或模型名称。

## 验证与局限

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
# 使用本地已配置的 API Key；全部为脚本新建的虚构任务，不读取历史任务，不调用手机：
python3 scripts/check_model_review.py
```

最终三组真实模型探针：故意错周的首稿被纠正且不修改另一条正确的当日重复事项；正确首稿原样通过；完整生成+复核保留正确的下周日期与提前两小时提醒。只测试模型与契约，没有新增手机日历事项，没有新后台验收。

开发中前两轮复核曾错误地把当日尚未来到的重复事项推迟一周，甚至编造“已过开始时间”的理由。首轮探针最初仅检查周期未检查首个日期，漏报此回归；现已补充。独立审查提示与时间事实缩小了问题，最终有限样本通过，但不能据此宣称普遍提高准确率或保证正确。原始各轮合成结果仅保留在忽略目录 `model-review-artifacts/`；汇总见 `evidence/model-review-validation.json`。

API 结构遵循 [OpenAI Docs：Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。结构化输出约束格式，不保证内容语义正确；模型复核也不能替代真实手机读回。
