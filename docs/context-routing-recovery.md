# 长测试带上下文时的路由复核失败

## 故障证据

更新超时修复后，实际八事项请求仍失败。此轮两次模型请求均返回 completed，整个理解阶段20.945秒；错误为 `Scheduling request must cite original text`，并非网络中断，没有进入手机日历执行。

首稿误判为 `calendar_mutation` 且生成了 conflicts 查询。复核发现用户要求新增，却纠正为 `calendar_schedule`，同时把摘要改写成原文证据，最终被精确引用检查拒绝。

根本问题是：复核 schema 根据首稿路由裁剪；只要首稿属于查询/排程/改删，就移除了 `calendar` 分支。复核提示还要求固定创建场景直接阻断，无法真正纠正路由。此外，schedule_request.evidence 的 schema 允许自由文字，而运行时只接受原文连续片段，生成契约与执行契约不一致。历史失败路由和前一轮改删请求增加了误判机会；之前仅用无历史的近似长文本回放，覆盖不足。

## 修复原则

- 复核始终拥有该版本的完整能力 schema，可把错判的查询/改删改回新建；首稿不是不可更改的状态。
- 当前消息决定动作，历史只补足指代，不把历史失败路径当作本轮指令。固定日期加“冲突不写入”仍由模型判断为新建，手机逐项真实检查；空档选时和修改旧事件保持各自语义。
- 路由分支的 query.mode 与实际接口对应：改删候选只允许 events，自主排程只允许 free_slots。schedule_request.evidence 使用同一套原文片段枚举，代码仍校验引用来源。
- 首次复核结果若仍违反执行契约，只允许一次额外模型复核，把具体校验错误返回给模型。不重做首稿，不自动改写业务参数；最终仍非法或复核明确block则不执行。所有审查轮次保留在本机记录。
- 生成前由模型独立清点当前请求的新增事项（最多8项；重复系列和连续跨天各算一项）。完整计划 schema 的条数与这份清单一致，执行契约校验逐项 ID，防止复核把八项缩成一项却放行。业务清点仍由模型完成，不使用关键词计数；清点本身也可能理解错误，复核发现时必须明确报告，不能假称保证不漏项。
- 提示中明确实际工具组合：固定时间新建的手机执行层自己读取最新占用并逐项检查冲突。因此“还没查到日历”不是拒绝生成固定时间候选计划的理由；模型仍不能在执行前宣称无冲突。
- 清点、生成、复核共用180秒；单个请求最多60秒和3次尝试。使用 Responses SSE 流持续接收，但只接受终态完整响应；半段 JSON、文本 delta 或终态前断线均不能成为可执行计划。

保持已有网络恢复、后台限制、任务去重与手机执行账本。此次仅改 Mac 侧，无须重装 iPhone App；失败的旧任务不自动重放。

## 验证

新增回归覆盖：错误改删首稿能纠正为创建、全部纠正路由可达、模式与原文引用契约一致、非法纠正结果可精确反馈一次、拒绝不被无限重试、清点后漏项被拒绝、流式断线不执行部分计划。已通过92项 Python 回归。

`check_context_routing.py --record <本机任务JSON> --live` 针对本次八事项测试：一次强制使用原错误首稿验证纠正出口，再两次完整生成并保留冻结的真实上下文。该命令会再次发送原任务和摘要到已配置模型，仅在获得该诊断用途授权后执行。没有手机 RPC 或日历写入。真实记录、完整模型输出在忽略目录；Git证据只包含聚合检查和耗时。

`tests/model_plan_replay.swift` 只链接 Foundation，用手机相同的计划与事件参数验证器检查模型回放输出，不导入 EventKit，不读写私人日历。模型回放通过也不能替代实际手机保存验收。

授权回放也暴露了后续问题，失败证据保留：`evidence/context-routing-replay-before-inventory.json` 中强制原错误首稿的纠正只剩一项；`evidence/context-routing-replay-before-streaming.json` 中一次复核错误阻断、一次真实连接中断后耗尽120秒。它们分别促成了独立清点、工具能力说明与流式接收/预算调整。当前完整回放结果见 `evidence/context-routing-replay.json`，设备验收状态另记 `evidence/context-routing-recovery.json`。

背景参考：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) 区分了结构遵循与内容正确；本次错误更具体地来自我们裁剪了合法纠正分支及契约不一致。

最终本轮验证：92项 Python 回归、8组 Foundation 与4组 EventKit 替身程序通过；3轮原始上下文回放全部通过（38.285/43.865/43.966秒），每轮8项再经手机同款 Swift 参数验证器通过。Mac 新服务已重启；重新连接后 AgentX 曾拒绝 TCP 连接，重启现有 App 恢复，RPC 确认前台、完全日历访问、没有开启执行窗口。未重新安装，也未自动重跑旧任务或实际写入测试日历；新的手机长任务验收仍待用户提交。
