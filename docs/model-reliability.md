# 模型超时与中断恢复

## 已观察到的根因

本轮八事项长测试读取日历成功后，在排程模型阶段16.3秒失败；同轮另一请求22.27秒失败，分别贴近旧16秒与22秒硬上限。旧适配器把超时和网络错误合并，没有保存失败请求的阶段与详细时间，无法进一步确认原始 socket 原因，不能将其全部归因于服务商宕机。旧版生成和独立复核共用该短预算，且暂时性故障不重试。

长测试还发生了路由错误：用户指定日期/时段，仅要求冲突不写入，却被送入自动选空档流程。现已在模型路由和复核规则中明确区分；固定安排走创建流程，实际每项冲突检查仍在手机执行。没有新增关键词路由器。

## 当前行为

- 保持配置的模型不变。首次理解的事项清点、生成及复核共用180秒；后续选时、改删、回答每阶段最多120秒，每次网络请求最长60秒；暂时性超时、连接中断、408/409/429及5xx最多共3次尝试，退避并尊重 Retry-After，受剩余阶段预算限制。鉴权、请求契约、额度不足、拒绝和过滤不盲目重试。
- 模型请求采用 Responses SSE 流，减少等待大响应期间完全没有返回数据的时间；只读取终态完整结果，绝不执行增量文本。终态前 EOF/断连走有限重试。流式接收不能保证消除网络或服务错误；单请求及阶段总预算仍有效。
- 结构化输出上限16000；只有服务明确返回 max_output_tokens 截断时，才在次数和时间预算内提高到32000重新生成完整响应。截断计划不执行，不将截断当成功。
- 每个完整模型响应先持久化到任务 JSON，以模型、输入、schema 的哈希绑定。复核重试复用该首稿。新任务的纯模型阶段允许一次进程中断恢复；同一请求的尝试次数也持久化。终态旧任务不自动重传，旧版没有恢复记录的中断任务保持原有保守行为。
- 推理重试和手机执行是两个层次。日历操作仍按原有任务ID、事项ID、lease和持久化账本保护；发送结果未知时只对账，不因为模型重试就重发写入。
- 模型处理中每2秒发送无日历副作用的状态心跳；连接状态不会仅因模型调用阻塞主循环而自动变成断连。手机显示正在理解、选时、修改决策或回答，终态显示具体失败类型。
- 前台任务窗口最长5分钟。首次进入后台最多45秒，系统可能更早结束；多次切换不重置后台时限，过期不能自动续期。模型可在Mac继续完成，窗口过期后只保存计划，用户主动继续才允许写入。没有延长iOS后台权利或新增保活机制。

`data/` 的任务记录新增 `model_checkpoints`、`model_runs`、`model_request_errors`，保存阶段、尝试次数、耗时、HTTP状态、request ID、response ID、usage、流事件数量及首事件耗时。原始模型响应只在本机忽略目录，API Key、请求头和服务商错误正文不记入报告。不增加发给模型的数据种类；事项清点和重试会再次发送相同任务/上下文并产生额外API费用。

## 验证

`bash scripts/test.sh` 覆盖网络故障重试、重试上限、Retry-After、额度/授权失败、截断、首稿断点恢复、前后台期限，以及原有日历防重复执行测试。

`python3 scripts/check_model_reliability.py --live` 使用合成八事项请求；第二轮主动注入一次复核连接中断。仅访问模型，不连接手机、不创建事项。聚合结果保存在 `evidence/model-reliability-live.json`。构建、模型回放与手机实测分别记录，不能互相替代。

协议依据：[OpenAI 错误与重试说明](https://developers.openai.com/api/docs/guides/error-codes)、[输出截断状态说明](https://developers.openai.com/api/docs/guides/reasoning)。当前故障不具备原始截断证据，长度调整属于对长结构化输出的防护。

本轮结果：78项 Python 测试、8组 Foundation 校验、4组 EventKit 替身程序通过，签名构建通过。两轮真实模型合成长计划分别36.088秒和29.660秒通过；后一轮复核首次连接人为中断，第二次请求恢复，首稿仅生成一次。修复版已安装并启动，Mac服务已重启，RPC确认原生宿主在前台且日历完全访问。手机新长请求的业务验收仍待进行。汇总见 `evidence/model-reliability-validation.json`。

后续用户实测仍失败，不能以上面的近似合成回放当作问题已经解决。原始请求及六轮上下文回放暴露的路由契约、漏项及真实网络故障详见 [上下文路由修复](context-routing-recovery.md)。流式协议依据：[OpenAI Streaming responses](https://developers.openai.com/api/docs/guides/streaming-responses)。
